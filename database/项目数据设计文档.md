# 项目数据设计文档（PR 项目需求主题）

本文档是《数据库设计文档.md》的补充，描述 **项目（Project）维度** 的数据分层设计。

## 1. 维度定位

项目维度与组织维度是**并列**的两大分析维度，项目**不是**部门（组织）的下属。

```text
分析维度
├── 组织维度 org
│   ├── employee    员工
│   ├── team        团队
│   ├── domain      领域
│   └── department  部门        ← 部门看板
└── 项目维度 project               ← 项目看板（与组织维度并列）
```

- **部门看板**：使用组织维度，按 `employee / team / domain / department` 向下钻取。
- **项目看板**：使用项目维度，按 `project` 单独分析，与组织维度互不从属。

在前后端代码层，二者是并列的一级维度：前端左侧导航“部门看板 / 项目看板”并列；后端各自独立接口与独立表，不共用 `org_type` 枚举。

## 2. 分层架构

项目维度只涉及 **PR（项目需求）** 主题（EC 故障不属于项目主题）。以 `project_id` 作为项目的唯一标识（不使用代理键）。

```text
业务系统 → ODS → DWD → DIM → DWM → ADS
```

| 层级 | 表 | 说明 |
|---|---|---|
| ODS | `ods_pm_project`（新增） | 项目主数据贴源 |
| DIM | `dim_project`（新增） | 项目维度 |
| DWD | `dwd_pr_fact`（沿用） | 已有 `project_id`，关联项目维度 |
| DWM | `dwm_pr_project_1d`（新增） | 项目 × 日 PR 汇总 |
| ADS | `ads_pr_project_kpi`（新增） | 项目 × 周期 PR KPI |

> 说明：组织链路是 DWD → DWM → DWS → ADS（需要跨员工向上滚动）。项目链路的 DWM 已经是“项目 × 日”最终分析粒度，无需再滚动，故不单独设 DWS 项目表，DWM 直接聚合到 ADS。

## 4. 项目维度 KPI 指标

| KPI 指标 | 计算口径 | 来源字段 |
|---|---|---|
| 需求承接数 | SUM | pr_assign_cnt |
| 需求完成数 | SUM | pr_complete_cnt |
| 需求完成率 | 完成数 ÷ 承接数 | pr_completion_rate |
| 准时交付率 | 准时数 ÷ 应交付数 | pr_on_time_rate |
| 平均处理时长 | 处理时长总和 ÷ 完成数 | pr_avg_process_days |
| 返工率 | 返工数 ÷ 完成数 | pr_rework_rate |
| 需求工时占比 | 需求工时 ÷ 有效工时 | pr_work_hours_ratio（暂无有效工时则置空） |

## 5. 建表 SQL（MySQL 5.7，utf8mb4）

```sql
-- 项目主数据（ODS）
CREATE TABLE ods_pm_project (
  project_id        BIGINT        NOT NULL,
  project_name      VARCHAR(128)  NULL,
  project_status    VARCHAR(16)   NULL,
  owner_employee_id BIGINT        NULL,
  start_date        DATE          NULL,
  end_date          DATE          NULL,
  etl_load_time     DATETIME      NOT NULL,
  etl_source        VARCHAR(32)   NOT NULL,
  etl_batch_id      VARCHAR(64)   NULL,
  etl_operation     CHAR(1)       NOT NULL,
  data_date         DATE          NOT NULL,
  PRIMARY KEY (project_id, data_date),
  KEY idx_data_date (data_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目主数据(ODS)';

-- 项目维度（DIM）
CREATE TABLE dim_project (
  project_id        BIGINT        NOT NULL,
  project_name      VARCHAR(128)  NOT NULL,
  project_status    VARCHAR(16)   NULL,
  owner_employee_id BIGINT        NULL,
  start_date        DATE          NULL,
  end_date          DATE          NULL,
  PRIMARY KEY (project_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目维度';

-- PR 项目日汇总（DWM）
CREATE TABLE dwm_pr_project_1d (
  stat_date           DATE          NOT NULL,
  project_id          BIGINT        NOT NULL,
  pr_assign_cnt       INT           NOT NULL DEFAULT 0,
  pr_complete_cnt     INT           NOT NULL DEFAULT 0,
  pr_due_cnt          INT           NOT NULL DEFAULT 0,
  pr_on_time_cnt      INT           NOT NULL DEFAULT 0,
  pr_rework_cnt       INT           NOT NULL DEFAULT 0,
  pr_process_days_sum INT           NOT NULL DEFAULT 0,
  pr_work_hours_sum   DECIMAL(12,2) NOT NULL DEFAULT 0,
  PRIMARY KEY (stat_date, project_id),
  KEY idx_project (project_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='PR项目日汇总(DWM)';

-- PR 项目周期 KPI（ADS）
CREATE TABLE ads_pr_project_kpi (
  period_type         VARCHAR(16)   NOT NULL,
  period_value        VARCHAR(32)   NOT NULL,
  project_id          BIGINT        NOT NULL,
  pr_assign_cnt       INT           NOT NULL DEFAULT 0,
  pr_complete_cnt     INT           NOT NULL DEFAULT 0,
  pr_completion_rate  DECIMAL(8,4)  NULL,
  pr_on_time_rate     DECIMAL(8,4)  NULL,
  pr_avg_process_days DECIMAL(8,2)  NULL,
  pr_rework_rate      DECIMAL(8,4)  NULL,
  pr_work_hours_ratio DECIMAL(8,4)  NULL,
  PRIMARY KEY (period_type, period_value, project_id),
  KEY idx_project (project_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='PR项目周期KPI(ADS)';
```

## 6. 前后端接口映射（并列关系）

组织维度与项目维度各走独立接口，互不混用：

| 维度 | 接口 | 关键参数 |
|---|---|---|
| 组织维度 | `GET /api/dw/kpi/pr` | `org_type` ∈ employee / team / domain / department |
| 组织维度 | `GET /api/dw/board` | `org_type` 同上 |
| 项目维度 | `GET /api/dw/project/kpi`（新增） | `period_type`、`period_value`、`project_id` |
| 项目维度 | `GET /api/dw/project/board`（新增） | `period_type` |

前端：

- 部门看板：组织维度下拉（团队 / 领域 / 部门）+ 时间周期
- 项目看板：项目维度 + 时间周期，调用项目维度独立接口

后端 `routes/dw.py` 不把 `project` 加入 `ORG_TYPE_LABELS`，而是新增独立的项目路由与 `project` 名称映射（`dim_project.project_name`）。
